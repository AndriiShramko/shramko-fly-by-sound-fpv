# FPV simulator rooms, tracks and onboarding: what established products do and what ShramkoSonicFPV should build once

Research note 03 for ShramkoSonicFPV, an open-source browser FPV simulator (WebGPU, Web Audio, PlayCanvas, TypeScript) that blind and low-vision pilots can fly by sound alone and sighted pilots can fly with headphones. Written 2026-11-07. Evidence tags: **MEASURED** (a study, a specification, a dataset or my own benchmark gives the number), **REPORTED** (a primary source such as a manual or patch notes states it, nothing was measured), **INFERRED** (my reasoning, not a fact). Numbers in brackets, such as [3], point to the Sources list.

## 1. Rooms and lobbies in established simulators

All rows are REPORTED: they come from each product's manual or official patch notes, not from measurements.

| Product | Hosting | Access | Seats | Modes | Control and failure handling |
|---|---|---|---|---|---|
| Liftoff (PC) | Developer-run multiplayer service; the host creates a room [1] | Public (listed) or private: the host types a room name and gives it to friends; in Micro Drones a custom name exists only for private sessions, a player says it works like a password, and the developer says it cannot be edited after creation because of service-provider limits [1][2] | 6 (Sep 2018), 8 (Dec 2023) [1] | Race, Dropout, Infinite Race, Freestyle, Free Flight [1] | Crash or reset sends you to spectate; late joiners spectate; host edits the room while it runs; battery-cell restriction with a list filter; mute, ban (2018), report (2023); Steam blocks honoured [1] |
| VelociDrone | The host is a "Race Manager" on VelociDrone servers in several regions, not on the host's PC [3] | Listed, hidden (join by unique name or friends list) or locked; region-bound [3] | 7 (10 in combat) [3] | Open, Single, Custom, Handicap, Relay, Event, Perpetual (Nov 2025) [3][4] | Full room means spectator; manager can kick, lock, hand over the role; if the manager drops, the server picks a new one, aborts the race and resets to a known state [3] |
| DRL Simulator | DRL servers; a Dec 2017 outage waited on the provider [5] | Room list, Quickmatch (Apr 2018), private rooms (Jan 2019), global "open match" invites (Jun 2019) [5] | Race 6 + 6 spectators, freestyle 12 + 12 [5] | Race, Freestyle; persistent room; vote on the next random track; ghost bots (Jun 2019) [5] | Ready button, host forces race or spectate, ownership hand-over, penalty for rage-quitters [5] |
| Uncrashed | In-game sessions since Feb 2024 [6] | List grouped by privacy, mode and latency; quick-play button; sort button added Apr 2025 [6] | At least 8 [6] | Race, free flight, Infinite Race (Apr 2025; the note does not say whether it is multiplayer) [6] | Host-only kick, spectate, delta time to the leader at checkpoints [6] |
| FPV.SkyDive, TRYP FPV | SkyDive: first multiplayer builds used P2P (Mar 2023) [7]. TRYP: online leaderboards shipped first, "the first step toward multiplayer" (Dec 2024) [8] | n/a | n/a | n/a | n/a |
| RotorHazard (real events) | The race director's own timer server on site [9] | Pilots are assigned to heats; heats belong to classes; later heats are seeded from earlier results [9] | Set by timer hardware [9] | First to X laps, most laps (with time or overtime), fastest lap, fastest 3 consecutive laps, team and co-op [9] | The director edits everything; each class has its own results and ranking [9] |

**Patterns that repeat across products.** (1) The server is the room and the host is a role: VelociDrone says the host "only" controls the session [3], and both VelociDrone and DRL added role hand-over [5][3]. Liftoff's July 2023 outage shows the cost of a relay that depends on a third-party cloud: the provider removed a service the multiplayer relied on and the studio rewrote the multiplayer framework in days [1]. (2) "Private" means unlisted plus a shared string, never a real password [1][3][5]; INFERRED: a guessable name is weak, an unguessable invite token gives the same flow with real privacy. (3) Spectating is the overflow valve for full rooms, crashed pilots and late joiners [1][3]. (4) Continuous racing converged: Liftoff Infinite Race (Jan 2018: "fly as many laps as you want; only the lap times matter") [1], Uncrashed (Apr 2025) [6], VelociDrone Perpetual Race (3 Nov 2025) [4]. (5) Skill mixing is handled by handicap, not by filters: VelociDrone's Handicap class delays each start by the difference between the pilot's lap time and the slowest pilot's, so equal efforts arrive together [3]; Liftoff players asked instead for a lobby filter on camera angle as a skill proxy (2017) [10]. (6) Votes are small: DRL rooms can vote the next random track, with "Featured" maps added to the vote [5]; Liftoff has post-race "honor votes" and a rating prompt at the results screen [1].

**What players complain about** (9 forum threads and the fix lists of the patch notes; no quantified corpus exists, see section 8). Dead waiting time and no practice inside a lobby: a 2016 thread asks for a queue so people can fly solo while waiting, and in 2017 a player notes that a private one-person lobby gives unlimited laps but records no times; the developer answered with Infinite Race [10]. Empty lobbies: a DRL player in May 2018 often found no one racing; a Micro Drones player proposed a fixed weekly meeting time in 2022 (INFERRED sign of sparse lobbies) [11][2]. Skill mixing and short time-outs: DRL's default multiplayer time-out was about two minutes, too short for hard tracks when teaching friends [11]. UI friction: a "show full rooms" tick box hid servers; creating a room was slow because every installed track was validated [10]. Lag spikes each time the first racer finishes (Uncrashed 2024) [12]. Pool size: a request for per-map play counts to judge whether a ranked pool is big enough [2]. Fragility: Liftoff's "join by name" broke for names containing "-", which every default room name had [1].

**How many people are there?** Average concurrent Steam players over the last 30 days: Uncrashed 629 (peak 1,090), Liftoff 529 (868), FPV.SkyDive 235, Micro Drones 90 (185), TRYP FPV 35 (75), DRL Simulator 17 (39) (MEASURED, third-party counters, read 2026-11-07) [13]. These counts include solo play. INFERRED: with rooms of 6 to 8, a design that needs strangers to meet in a room starves in most hours, so the first release must work with one pilot and ghosts.

## 2. Tracks, timing, ghosts and ratings

**Real dimensions (MEASURED from specifications and league listings).**

| Source | Number | Note |
|---|---|---|
| FAI F9 (2025) | Obstacle to cross: free space of at least 1.5 m diameter centred on the optimal line. Obstacle to avoid: at least 2.5 m free diameter. Must be visible on a standard FPV camera at 30 m. Circuit at least 250 m, three laps, a 60 to 120 degree turn before the first gate recommended [14] | Small gates "not recommended" because simultaneous passes collide [14] |
| MultiGP standard | Gate opening 5 x 5 ft (1.524 m) [15]; collegiate rule: opening at most 7 x 6 ft, flags at least 8 ft tall [16][17] | Lap time starts when the first gate is passed [16] |
| MultiGP whoop | 25 in square opening (about 63.5 cm) [18] | Whoop and micro gates exist as separate shop categories [18] |

**Editors and gate types (REPORTED).** The editors described in these sources share one model (INFERRED from their feature lists): an ordered list of crossing objects (square or round gates, start/finish, checkpoints and triggers) plus avoid objects (flags, pylons, blocks). Micro Drones' 2025 builder offers gates, triggers, checkpoints, resizable blocks, spline placement, grid and point snapping and over 175 items, with a thumbnail and description per track [19]. VelociDrone has over 2,000 objects, gates "in standard sizes" for major leagues, a "MultiGP PRO Spec" track type and a shared database: over 1,000 base tracks plus over 40,000 online [20][4]. DRL's editor (2018) has 200+ assets and gained directional gates in 2019 [5]. FPV.SkyDive's builder caps a track at 30 visible gates and 50 detection waypoints, 8 tracks per user, and erases the personal best on every edit because an edit can change the flying path [7]; INFERRED lesson: publish immutable track versions and key every time to a version.

**Showing the course (REPORTED).** VelociDrone draws an indicator in front of the next gate, edge-of-screen arrows when it is off screen, turns it red when you approach from the wrong side, in four colours [3]. Micro Drones uses an arrow for the next checkpoint and spheres for later ones, with a setting for how many checkpoints ahead to show, and in 1.0 smoothed the guide path between checkpoints [19]. Liftoff's "Checkpoint Altitude" assist makes the drone match the next checkpoint's height [21]. VelociDrone draws a "race line" from ghost data, cyan fading to magenta over the lap [3]; DRL has a "Raceline" whose visibility it improved in 2019 [5]. FAI asks that the path through an obstacle be "clearly marked" [14].

**Timing and fouls (REPORTED unless noted).** Real events time from the first gate (qualifying) or from the start signal (elimination); the start is "arm your quads", 2 to 4 s of silence, one tone, no countdown [14]. A missed obstacle invalidates the lap unless the pilot corrects it at once and safely [14]. RotorHazard offers "hole shot" (first crossing starts lap 1), "first lap" (first crossing ends lap 1) and "staggered start" (each pilot's clock starts at their own first crossing), a minimum-lap-time filter, and win conditions first to X laps, most laps, fastest lap, fastest 3 consecutive laps [9]; MultiGP's collegiate rules ask pilots to submit their fastest three consecutive laps of the day [17]. Simulators replace judges with automatic rules: a crash resets you to the last gate passed (VelociDrone default), Event mode red-flags a crashed pilot at the next gate and ranks by lap and gate number [3], Uncrashed's double reset returns you to the last valid gate and shows delta time to the leader at checkpoints [6]. I found no published missed-gate penalty rule in any simulator beyond these.

**Ghosts and leaderboards (REPORTED).** Liftoff ghosts (2016) replay your fastest five of the last twenty runs on the same track; Micro Drones 1.0 stores a recording with every multiplayer high score [1][19]. VelociDrone Nemesis loads the ghosts of the pilots two places above and below you on the leaderboard, over 50,000 recorded flights, so racing never needs anyone online [3][20]. DRL "Opponents": Self, Top 5, or Rival 5 [5]. Boards are split to stay fair: VelociDrone only accepts times from Single Class [3]; DRL groups by drone class and keeps a stock-parts "Leaders" board [5]; Micro Drones adds a "Purist" toggle [19]. Micro Drones initially kept leaderboard scores only from multiplayer sessions [19] (INFERRED: a server-observed session is harder to forge). VelociDrone shows 15 times per page, exports CSV to seed events, and runs a weekly time trial on one track [3].

**Sharing and rating.** Steam Workshop voting is binary (up or down) and the API's score is "the bayesian average for up votes / total votes"; lists sort by all-time votes, by votes in a "trend" window, or by votes up [22] (REPORTED). Liftoff added a rating prompt on the race results screen [1]; VelociDrone lets you sort tracks by total ratings [3]. YouTube reported in 2009 that the overwhelming majority of rated videos had five stars, so ratings worked as a "seal of approval", and asked whether thumbs up and down would be more effective [23] (REPORTED). The mean fails for small n and the Wilson lower bound fixes it: score = (p + z²/2n - z·sqrt((p(1-p) + z²/4n)/n)) / (1 + z²/n) with p = share of up votes, n = votes, z = 1.96 for 95% [24]. A coverage study found the plain Wald interval erratic and recommends Wilson (or Jeffreys) for small n [25] (MEASURED). Computed from the formula: 1/1 up gives 0.21, 5/5 gives 0.57, 20/20 gives 0.84, 45/50 gives 0.79, 90/100 gives 0.83, 450/500 gives 0.87; a Beta(3,1)-prior average gives 0.80, 0.89, 0.96, 0.89, 0.89, 0.90 for the same inputs. INFERRED choice: store up and down counts per track version, sort "Top" by Wilson lower bound, keep a separate "New" shelf for n below 5 (otherwise new tracks sink), and a "Trending" shelf by votes in the last 14 days; Evan Miller also notes that positive ratings per view or download can be more informative than per rating, so count finished runs as the denominator when available [24].

## 3. Procedural tracks inside an arbitrary scanned scene

**Prior art (REPORTED).** FPV Freerider shipped a "Racetrack Generator" in 2018 [26]. Endless FPV (released 23 Oct 2026) stitches an endless course from segments in themed "decks" of more than 20 segments each, and lets players build a custom deck [27]. I found no generator in Liftoff or VelociDrone, whose pages describe manual editors [20]. Research: Togelius et al. evolve closed b-spline tracks scored on "the right amount of challenge", progress variance and top speed, and a radial control-point layout rules out loops [28]; the AirSim Drone Racing Lab randomises gate shape, scale and pose and scores a track by curvature per unit length and next-gate visibility [29]. I found no paper on generating drone-racing courses inside a Gaussian-splat scan, so the pipeline below combines published parts (INFERRED as a whole).

1. **Classify space as occupied, free or unknown.** OctoMap models free, occupied and unmapped space: occupied from sensor end points, free from the observed ray between sensor and end point [30]. Splat-Nav turns every Gaussian into a gamma-percent confidence ellipsoid (chi-square quantile), bins ellipsoid bounding boxes into a conservative occupancy grid, dilates it by the drone radius with a MaxPool3D kernel, and lets gamma vary with local map quality [31]. It cannot see obstacles missing from the scan [31], and casually captured radiance fields show floaters and wrong geometry off the camera path [32]. INFERRED rule for "well-scanned free space": a voxel is usable only if at least K training-camera rays crossed it before their first surface hit (K of 3 to 5, tune on scenes with known errors), it lies within D of the capture trajectory (D of 1.5 to 2 m), and the opacity-weighted splat density there is below a threshold; everything else counts as occupied.
2. **Clearance field.** The exact Euclidean distance transform runs in linear time [33]. MEASURED here: SciPy took 1.96 s for 8.4 M voxels (10 cm voxels, a 25.6 x 12.8 x 25.6 m hall) and 7.0 s for 28.3 M [34]. INFERRED: generate offline in the Python API when a scene is added, store tracks as data, and never compute this in the browser.
3. **Gate sites.** Candidates are clearance maxima with value above r_min = gate half-diagonal plus margin (a 25 in whoop opening has a half-diagonal of 0.45 m; with a 0.3 m margin r_min is 0.75 m; INFERRED), the gate normal follows the free-space principal axis, and a free approach tube is required on both sides. FAI asks for free space of at least 1.5 m diameter on the optimal line and a flight path between obstacles that allows smooth flight [14].
4. **Path.** Dijkstra or A* on the 26-connected dilated grid, cost = step length + lambda / clearance squared. Splat-Nav seeds its trajectory the same way before refining [31]; Fast-Planner runs a kinodynamic path search, then B-spline optimisation with Euclidean-distance-field gradients for clearance and smoothness [35]. INFERRED: a deterministic grid search makes (scene, seed, skill) reproduce the same track, so a track can be shared as three numbers.
5. **Smooth and limit speed.** Centripetal Catmull-Rom is the only parametrisation that guarantees no cusps or self-intersections inside a segment [36]; after smoothing, re-check clearance on the distance field. Speed cap v(s) = sqrt(a_lat / curvature(s)) from a = v² x curvature (INFERRED, kinematics). The AirSim baseline planner used vmax 30 m/s and amax 15 m/s² on eight of its nine tracks (5 and 2 on the ninth), whose curvature metrics run from 0.02 to 0.09 per metre [29] (MEASURED parameters); a survey of autonomous drone racing states that speeds exceed 80 km/h and accelerations 4 g [37] (REPORTED); beginner classes should sit far below, e.g. 0.5 g (INFERRED).
6. **Difficulty by generate-and-test.** Produce 50 to 200 candidates per (scene, skill tier), fly each with a bot limited to that tier, and keep tracks whose bot lap time and crash rate fall in the target band; this mirrors the fitness terms of [28] and the metrics of [29]. INFERRED sound analogue of "next-gate visibility": the share of the path where the next gate's audio cue is unoccluded, plus turn-rate demand.
7. **Scaling (INFERRED starting values, tune by playtest).** Gate count N = clamp(round(L / s), 4, 16), L the loop length and s the mean spacing: at least 6 times the gate opening for beginners, 3 to 4 times for experts; L at most 0.6 of the longest closed free path found. Tier 1: square gates only, turns up to 60 degrees, openings 1.5 times nominal. Tier 2: add flags, hurdles, 90 degree turns. Tier 3: add dive, ladder, split-S and tower gates as defined by MultiGP [38]. FAI recommends a 60 to 120 degree turn before the first gate to reduce start collisions [14].

## 4. Multiplayer in a browser on a small budget

| Transport | Delivery | Server side | Status |
|---|---|---|---|
| WebSocket | Reliable and ordered over TCP, so one lost packet stalls newer data (head-of-line blocking) [39] | Any HTTP reverse proxy | Universal; Gaffer notes the popular web games of 2017, such as agar.io, ran on it [39] |
| WebRTC data channel | Per-channel `ordered`, `maxRetransmits` and `maxPacketLifeTime` allow UDP-like delivery [40] | Signalling plus NAT traversal (INFERRED) | FPV.SkyDive's first multiplayer builds were P2P [7] |
| WebTransport | Streams plus unreliable datagrams over HTTP/3 [41] | An HTTP/3 (QUIC) endpoint [41] | MDN lists it as Baseline "newly available" since March 2026 [41] |

**Choice (INFERRED).** Start on WebSocket behind the existing reverse proxy and hide it behind a small transport interface, so datagrams over WebTransport can replace the state channel later without touching rooms. Reasons: at 6 to 8 pilots the packets are tiny, PlayCanvas's own multiplayer tutorials use WebSockets (Socket.IO, Colyseus) [42], and Gaffer's objection to TCP concerns packet loss (INFERRED: worst on mobile and Wi-Fi links) [43]. Drone flight needs no server physics: each browser simulates its own drone, and the server relays states and referees the race.

**Tick rate and interpolation.** Gaffer's rule (REPORTED, tuned at 2 to 5 percent loss): buffer three send intervals so two packets in a row can be lost, plus a jitter margin; he quotes 300 ms at 10 snapshots/s (350 ms used with jitter), 150 ms at 30 and 85 ms at 60 [43]. Colyseus defaults to 20 state patches per second [44]. INFERRED: 30 Hz states from each pilot, one batched snapshot per room per tick, 100 to 150 ms interpolation for remote drones (your own drone is local, so the delay only affects what you see of others). Production notes from sims: Liftoff 1.5.9 made network traffic scale with the number of active players [1]; VelociDrone staggers joins so a burst of joiners does not freeze the client [4].

**Size of a state and of a ghost.** Fiedler packs a quaternion into 29 bits (smallest three, 9 bits each) and bounds velocity to 32 m/s in 11 bits per axis [45]. INFERRED: position 3 x 20 bits, orientation 29 bits, velocity 33 bits and one flag byte give about 16 bytes per pilot state, so my 24-byte test message is conservative. A relayed room costs 24 B x 8 pilots x 30 Hz = 5.8 kB/s per listener, about 60 kbit/s down and 22 kbit/s up per pilot if each message carries roughly 60 bytes of TCP, IP and WebSocket headers (INFERRED arithmetic). Ghosts reuse the same stream: at 10 Hz plus velocity with Hermite interpolation, which Gaffer shows to be smooth at 10 snapshots/s [43], a 60 s lap is about 10 kB before compression (INFERRED). Micro Drones saves a recording with every multiplayer high score and VelociDrone holds over 50,000 ghost flights [19][20].

**Measured relay cost (MEASURED, localhost, no TLS, Windows dev box, so a lower bound).** One Python asyncio process using `websockets` and per-tick batching: 200 pilots (25 rooms of 8) used 24 percent of one core; 400 pilots (50 rooms) used 51 to 57 percent with the age of a pilot's own state in the snapshot at 36 ms median and 78 ms at the 99th percentile (this includes up to 33 ms of batching); at 800 pilots the loop fell behind (tick lateness over 2 s) [34]. Largest sim by average concurrency has about 630 players in all modes [13], so a single process is enough for years of growth.

**Right shape for one small Docker service beside a Python API (INFERRED).** (1) A separate container with one asyncio process, in-memory rooms, WebSocket only, behind the same TLS reverse proxy. (2) The API stays the source of truth for accounts, tracks, ratings, clubs and results. (3) Join flow: the client asks the API for a room, the API returns a short-lived signed ticket (room id, pilot id, role, expiry of about 60 s), the client opens the WebSocket with it. (4) The service calls the API only for three things: validate ticket keys, persist finished runs (idempotent run ids) and load persistent rooms at start-up. (5) Colyseus gives rooms, locked, private and unlisted flags, auto-lock when full, seat reservation and reconnection out of the box [44]; adopt its vocabulary even if the code stays in Python. (6) Referee, do not simulate: accept a run only if gates were passed in order, speed stays under the class limit and positions are continuous; Liftoff patched exploits where illegal drone setups set records, which shows the risk of trusting clients [1]. Cost: a Hetzner Cloud Regular Performance plan is listed at EUR 6.49 per month excl. VAT, and EU servers include at least 20 TB of traffic [46]; 400 pilots streaming around the clock would move about 8 TB per month (INFERRED), so bandwidth is not the constraint.
